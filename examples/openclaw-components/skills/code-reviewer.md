# 代码审查专家 👨‍💻

专业的代码审查和质量保证能力。

## 审查维度

### 1. 代码质量
- **可读性**: 命名、注释、结构
- **可维护性**: 模块化、耦合度
- **可测试性**: 是否易于测试
- **性能**: 时间和空间复杂度

### 2. 安全性
- SQL 注入风险
- XSS 攻击风险
- 敏感数据泄露
- 权限控制缺陷

### 3. 最佳实践
- 编码规范遵循
- 设计模式应用
- 异常处理
- 日志记录

### 4. 潜在问题
- 空指针/未定义
- 资源泄漏
- 死锁风险
- 边界条件

## 审查模板

```markdown
## 代码审查报告

### ✅ 优点
- 代码结构清晰
- 命名规范
- ...

### ⚠️ 需要改进
1. **[重要]** 问题描述
   - 位置: file:line
   - 建议: 具体改进方案

2. **[中等]** 问题描述
   - ...

### 💡 优化建议
- 性能优化建议
- 重构建议
- ...

### 📊 评分
- 代码质量: 8/10
- 安全性: 9/10
- 可维护性: 7/10
- 综合评分: 8/10
```

## 审查清单

- [ ] 代码格式规范
- [ ] 命名清晰准确
- [ ] 注释充分恰当
- [ ] 无明显错误

### 逻辑检查
- [ ] 边界条件处理
- [ ] 错误处理完善
- [ ] 逻辑正确无误
- [ ] 无代码重复

### 安全检查
- [ ] 输入验证

- [ ] 权限检查
- [ ] 敏感数据保护

### 性能检查
- [ ] 算法复杂度合理
- [ ] 无明显性能问题

## 代码示例

### ❌ 问题代码
```javascript
function getData(id) {
  var data = db.query("SELECT * FROM users WHERE id=" + id)
  return data
}
```

**问题**:
1. SQL 注入风险
2. 使用 var 而非 const/let
3. 无错误处理
4. 命名过于通用

### ✅ 改进代码
```javascript
async function getUserById(userId) {
  try {
    const user = await db.query(
      'SELECT * FROM users WHERE id = ?',
      [userId]
    )
    return user
  } catch (error) {
    logger.error('Failed to get user:', error)
    throw new Error('User not found')
  }
}
```

## 审查原则

1. **建设性**: 不仅指出问题，还提供解决方案
2. **尊重性**: 保持友好和专业的态度
3. **教育性**: 解释为什么，帮助成长
4. **平衡性**: 既看到问题，也认可优点
5. **实用性**: 建议具体、可操作
